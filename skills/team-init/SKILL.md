# Set a repo up for the team process

Work on a branch and open a PR at the end; do not push to `main`. Templates are in `${CLAUDE_SKILL_DIR}/../../templates/`, scripts in `${CLAUDE_SKILL_DIR}/../../scripts/`.

1. **If the working directory is not the repo** (a host at a parent folder), ask which repo, work inside it, and tell the owner at the end that shifts must start in the repo folder, since `CLAUDE.md` and memory are read from the working directory. **If a `discovery-brief.md` exists** (from the `discover` skill), take from it what it answers: the profile and platforms, the content of `PRODUCT.md`'s four headings, the licence (write the `LICENSE` file from the decision), and `ROADMAP.md`'s sections from "First version" and what was parked; ask only what it leaves open. **Ask two things** if CLAUDE.md does not already say them: the profile (`apple`, `web`, `none`) and whether the project has UI now (design agent from the start) or not yet (engineering only; add design when there is UI). Everything else has a default.
2. **Labels:** run `scripts/gh-labels.sh` in the repo.
3. **CLAUDE.md:** append `templates/CLAUDE.md.snippet`, make its first line the project's own `# <name>` heading (the shift is announced with it), set `Role:` to `engineering` and `Profile:` to the answer, fill the project facts you can find (simulator, viewports, ports, devices) and delete the other profile's lines. Ask the owner what to put on the `Plugin feedback:` line (the maintainer session's name as the app shows it, for `SendMessage`; an id may not resolve; with "else an issue on <owner>/agent-team" as the fallback for a session without that tool); if they want none, delete the line, since a shift sends nothing when it is unset. Keep the project's existing CLAUDE.md content; move process rules that the skill already covers out of it and leave project facts.
4. **Worktree hook, if the project caches per checkout** (build folders under `$TMPDIR`, anything named for the path): create `.agent-team/hooks/worktree-removed` from `templates/.agent-team/hooks/worktree-removed.example`, computing the exact names the project's scripts use, executable and committed. **State file and roadmap:** copy `templates/.agent-team/state.md` to `.agent-team/state.md` and `templates/ROADMAP.md` to `ROADMAP.md`. Fill the roadmap from the brief's "First version" (its must-dos for Now and Next, its parked items for Not now) when `discovery-brief.md` exists, else from open issues and milestones if there are any, marked "first draft by engineering, the owner orders it".
5. **Git ignore:** append `templates/gitignore.snippet` to `.gitignore`. **Builders' standing brief:** copy `templates/.agent-team/builder-brief.md` to `.agent-team/builder-brief.md` and fill what the repo and CLAUDE.md already say (lock names, disk floor, build folders, attribution, screenshot content rules); builders read it first, so the per-task briefs stay short.
6. **Issue templates and the decision workflow:** copy `templates/.github/` into the repo's `.github/`, and put the owner's GitHub login (`gh api user --jq .login`) into the `assignees:` line of `ISSUE_TEMPLATE/owner.md`, so an owner call filed from the template is assigned to them; the agents assign theirs with `--assignee @me` (see `reference/messages.md`). Make sure the `bug` label exists (GitHub creates it by default; `scripts/gh-labels.sh` adds it if not).
7. **A repo that already has a design changelog or memory files:** move the existing changelog file into `design/changelog/0000-archive-<last date>.md` unchanged (it sorts oldest and is never edited again; new entries are one file each). If the design files have other names (for example `MYAPP-DESIGN.md`), rename them with `git mv` to `DESIGN.md` and `TOKENS.md` and fix the links. Then read the project's memory directory (`~/.claude/projects/<project>/memory/`): delete every rule the skill now covers, keep project facts only (devices, build quirks, measurements), and say in the PR what was removed.
8. **If the project has UI:** create `design/README.md` from the template, the folders `design/boards`, `design/components`, `design/mockups`, `design/built`, `design/changelog` (with a `.gitkeep` each), and empty `DESIGN.md` and `TOKENS.md` with a heading per known screen. Create `PRODUCT.md` with the headings "What it is for", "For whom", "What it is not", "Principles": filled from `discovery-brief.md` when one exists (its "Product" section has the four), else empty. The design agent fills or refines them with the owner; do not invent product or design content. A project without UI gets the same `PRODUCT.md` when a brief exists, since the brief's answers are the project's, not the design role's.
9. **`ARCHITECTURE.md`:** if the repo has code, write the one-page version described in `reference/architecture.md` of the team-process skill from what the code shows, marked "first draft by engineering, to be corrected". If the repo is empty, a heading and a sentence.
10. **Repository settings only the owner can change:** require PRs on `main` (not available on free private repos; then the skill's rule is the only guard), turn on "Automatically delete head branches" under Pull Requests (agents cannot delete branches, so merged branches pile up otherwise), and, if wanted, a second GitHub account for design as a collaborator.
11. **On a Mac that runs agents:** check that `agentlock` is on the PATH and `~/.agentlock/guard.conf` exists; if not, say what to copy from `hooks/guard.conf.example`. The plugin's hooks do the rest.
12. **Open the PR** with the list of what was added, and report what the owner still has to do (step 10, and, if design is not a Claude Code session, the first message for it from `templates/design-session-prompt.md`).
