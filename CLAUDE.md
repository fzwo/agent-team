# agent-team: how this repo is maintained

This repo is the plugin that defines the owner-plus-two-agents process. Its maintainer (a Claude session, usually in the cloud) follows the parts of that process that fit a one-agent repo. The owner's agents on the Mac review each released version on the machine; that step is not replaceable from here.

- **Every change goes through a branch and a PR.** Never push to `main`. Merge only after a clean review round. The version bump in `.claude-plugin/plugin.json` and the round's entry in `DECISIONS.md` are commits on the PR branch, made before the merge, so `main` is never pushed to directly.
- **Run `tests/run.sh` before opening the PR** and after every fix. A change to a script adds or changes a test for it. A bug found on the Mac gets a test that reproduces it before the fix, where the suite can express it.
- **Adversarial review on every PR**, by a fresh subagent given the brief in `agents/reviewer.md`, the diff, the full touched files and the test output, not the author's conclusions. A reviewer works on an export of the commit under review (`git archive <commit> | tar -x -C <its scratchpad>`), never on the shared checkout: the maintainer switches branches there, and a script rewritten or removed under a running suite gives phantom failures (round 45). Mutation tests run on that export too. The tiers, the re-review rules (the same reviewer resumed, the cold-cache fallback, a fresh reviewer for the last clean round of a high-tier PR) are those of `skills/team-process/reference/review.md`, with one reading for this repo: documents are `low`; scripts are `standard`; anything that deletes files, takes locks, or runs as a hook is `high`, and the higher tier wins where both apply (the suite deletes its scratch directory, so it is `high`).
- **Facts versus principles:** the plugin states principles and mechanics; tool-version-bound facts belong in a project's CLAUDE.md with the version next to them, and the plugin carries at most a dated example.
- **The record:** `DECISIONS.md` gets an entry per round, newest first, crediting who found what. Corrections to the record are made in the record, not only in chat.
- **Honesty over agreeableness** applies to the maintainer too: when an agent's review is right, say so and fix it; when the owner's instinct beats the rule, say so in the entry.
